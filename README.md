# Campaign Site Factory

نظام لإنشاء وإدارة مواقع حملات إعلامية متعددة من قالب واحد مشترك.

- **مصنع المواقع** (`factory/`) — لوحة تحكم داخلية تُنشئ وتدير مواقع الجهات، تعمل على **Render**.
- **موقع كل جهة** (`tenant-template/`) — الموقع العام + لوحة الإدارة، يُنشر لكل جهة كمشروع
  **Vercel** مستقل عبر المصنع.
- **قاعدة البيانات**: خادم Postgres واحد على Render، تستضيف بيانات المصنع وكل الجهات معًا —
  كل جهة معزولة في مخطط (schema) خاص بها على نفس الخادم.

للتعليمات الكاملة من المتطلبات حتى أول موقع منشور، راجع **[`DEPLOYMENT_GUIDE.md`](./DEPLOYMENT_GUIDE.md)**.

## بنية المشروع

```
campaign-site-factory/
├── DEPLOYMENT_GUIDE.md    ← ابدأ من هنا
├── tenant-template/        قالب موقع الجهة — يُنشر على Vercel
│   ├── index.html، admin.html
│   ├── api/[...path].js
│   ├── lib/db.js، lib/db.test.js
│   ├── migrations/
│   └── README.md
└── factory/                 لوحة تحكم المصنع — يعمل على Render
    ├── server.js، dashboard.html
    ├── api/[...path].js
    ├── lib/
    ├── migrations/، tenant-migrations/
    ├── render.yaml
    └── README.md
```

## أهم الميزات

- مشاركة عبر X وواتساب وفيسبوك، مع تتبّع لكل منصة في التحليلات
- هوية بصرية ديناميكية لكل جهة (اسم، شعار، ألوان، منصات مفعّلة) — قابلة للتعديل من لوحة المصنع
  في أي وقت بعد الإنشاء، بما في ذلك رفع/استبدال الشعار
- مصادقة ثنائية إلزامية لمشرفي المصنع، تشفير AES-256-GCM لمفاتيح الوصول، سجل تدقيق كامل
- إنشاء جهة جديدة بالكامل (قاعدة بيانات + موقع منشور) عبر معالج من 6 خطوات، بمتابعة تقدّم حيّة
- Rollback تلقائي عند فشل أي خطوة أثناء الإنشاء

## الحالة

كل الكود مفحوص صياغيًا ومُختبَر بمحاكاة قاعدة البيانات (`npm test` في كل من `tenant-template/`
و`factory/`)، وشُغِّل خادم `factory/server.js` فعليًا محليًا مع طلبات HTTP حقيقية للتحقق من
التدفق الكامل. لم يُختبر بعد ضد Vercel أو Render حقيقيَّين — الخطوة الأولى في
`DEPLOYMENT_GUIDE.md` هي تجربة كاملة على جهة وهمية قبل أي بيانات حقيقية.
